### 水の状態（05）

- `NpcWaterState` を追加した。次を1回の計算でまとめる。
  - 目が水中か
  - 浅瀬に立っているか
  - 足下の深さ（最大32）
  - 水面までの距離
  - 水面の上が開いた空気か（氷・天井ではないか）
  - 最寄りの空気
  - 最寄りの岸
- 水中では `observe()` の `water` として計画AIへ渡す。
- 水中安全の判定は、水面が閉じている（氷・天井）ときは空気の残量を待たずに退避を始めるようにした。
- `water_state_reports_depth_and_open_surface`: 観測に深さ・水面・空気が入ることを確認する。
- `water_state_leaves_under_ice_before_air_runs_low`: 20Tick以内に退避が始まらない → 開始する。

### AIへの要求（04）

- 要求の枠を分けた。所有者のチャットと計画は「急ぎ」の枠を使い、定期発言や完了の発言には待たされない（`NpcService.requestSlot(tick, urgent)`）。
  - `owner_chat_not_delayed_by_periodic_speech`: 40Tick以上待たされる → すぐ送信される。
- 計画とセッション開始のエラー後の待ち時間を、固定の30秒から2・4・8・16・30秒と延ばしていく方式にした。成功すると初期値に戻る。
- チャット（発言のみ）のターンの待ち時間の上限を45秒にした。計画は設定値（既定180秒）のまま。

### 構造（01）

- GameTest 32ファイル（約9,300行）を、新しいソースセット `src/npcGameTest` に移した。
  - 開発時の起動では、同じMODとして読み込む（`build.gradle` の `mods`）。
  - 配布JAR（`npcJar`）には含まれない。JARのクラス数は186で、GameTestは0。
  - 登録は、`avatarcraft.npcGameTest` が有効なときだけリフレクションで行う。
- UI確認用の `NpcBuildUiQa` は製品側のフックから呼ばれるため、製品側に残した。そのため、試験と共用していた設計図 `house()` を `NpcBuildUiQa` に移した。

## 実施しなかった項目と理由

| 項目 | 理由 |
| --- | --- |
| 精密な編集移動の高速化 | 50%の入力と常時の減速で試した。`tall_tree_builds_walkable_stairs` が20回中4回失敗し、従来の速度では20回中0回だった。自作の階段の形が変わることが原因とみられるため、従来の速度に戻した。階段の作り方の改善が先に必要 |
| B6 再探索中の移動の継続 | 再探索の多くは地形の変化で前方が無効になった場合で、古い経路を進むと危険がある。最終点の減速（03のB1）で、区間の終わりの停止は一部改善した |
| 葉のセルを立ち位置にする | 地面から葉を切る方式（05）で、試験の樹冠を回収できた。立ち位置の葉を先に掘る処理は、作業経路との整合が大きく、効果に見合わないと判断した |
| LLMの往復を1回にする・ストリーミング・計画のキャッシュ・effortの調整 | どれも、実AIの接続で応答の質と所要時間を比べないと効果を判断できない。今回は模擬AIで確認できる範囲（要求の枠、待ち時間、エラー後の待ち）に限った |
| NavigationService の統合・`NpcSkills` の分割 | 約2,400行のクラスを分ける大きな変更になる。機能の修正と同時に行うと回帰の切り分けが難しいため、機能が落ち着いた後の別作業とする |
| はしごの下り、斜めの落下 | 上の表のとおり、物理の挙動との整合が取れないため |

## 途中で見つけて直した問題

- **雪の層の試験**: 短い詰まり規則のジャンプが、精密移動のゆっくりした接近中に発火した。
  - 修正: 精密移動を対象外にし、水平速度がほぼ0のときだけ発火するようにした。
- **作業経路の試験**（`recorded_drop_return_repairs_real_steps`）: 停止の判断を10秒にしたところ、長い探索の待ちで失敗した。
  - 修正: 作業経路は20秒のままにした。
- **畑の収穫試験**（`farm_real_harvest_replant_eight`）: 修正版で20回中1〜2回失敗した（変更前は30回中0回）。
  - 二分探索で、詰まり規則のジャンプが原因と特定した。
  - 修正: ジャンプは段差に押し付けられているときだけにし、農地の上では行わない。修正後は20回中0回。
- **チャットの優先試験**: 同じ環境で並行して動く他のチャット試験が、共有の要求枠を使っていた。
  - 修正: この試験を独立した環境にした。
