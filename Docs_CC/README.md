## 結論

既存の調査（`Docs/NpcArchitectureReview20261025.md`、`NpcV7FiveTaskVerification20261026.md`、`NpcNeoDiamondInvestigation20261026.md`、`NpcWaterPoolStudy20261026.md` など）の結論は「モデル容量より実行処理が問題」だった。今回コードを読み直しても同じ結論になる。4つの課題には、それぞれ数行〜数十行で直せる具体的な原因がある。

| 課題 | 主な原因（根拠） | 影響 |
| --- | --- | --- |
| 経路の正確性 | 経路探索の開始時に周囲128ブロックの**動く生物を壁として固定**する（`NpcWalkingRoute.java:227-245`）。move_toの終点許容が**0**（`NpcSkills.java:1337`）。落下は1段まで（`WalkingPathSearch.java:88`）。水・はしご・水没ブロックは通れない | v6/v7検証で最も多い失敗 `No supported walking route within 128 blocks` |
| 低速移動 | `setSpeed(倍率×0.1)` により、Mobの加速が速度の2乗になる（`NpcStepMoveControl.java:42`）。通常歩行1.6倍は**プレイヤー歩行の約1/4**（推定）。ダッシュ条件の「周囲0.35に壁なし・高さ変化なし」が厳しすぎる（`NpcSkills.java:70-80`） | 常に遅く見える。慎重なのではなく速度の換算が誤っている |
| 即時反応 | 反射層は溺水回避（`NpcWaterSafety`）だけ。防御は学習モデルの候補の1つで、長い技能の実行中は誰も被弾を確認しない。指示はLLMを2往復しないと実行されず、途中で捨てる規則もある | 攻撃されても作業を続ける。指示への反応が数秒〜数十秒遅れる |
| 周辺認識 | 視線判定が `ClipContext.Block.COLLIDER` なので、葉が視線を完全に遮る（`NpcSkills.java:330`）。立ち位置探索が葉を拒否する（`isFaceSturdy`、`NpcLocalWorld.java:1115`）。水は「深さ5超＝不明」とまとめられ、天井も確認しない | 樹冠内の原木を掘れない。深い水で地形観測が空になる |

## 優先して行う修正（効果が大きく、変更が小さい順）

1. **移動速度の換算を直す**（03）。**2026-10-26に実施済み**。歩行は1.126→4.405ブロック/秒、ダッシュは3.603→5.727ブロック/秒で、どちらもプレイヤーの102%になった。精密な編集移動は従来の速度のまま残した（03の「実施結果」）。
2. **経路探索から動く生物を外す**（02）。**2026-10-26に実施済み**。生物がいたセルを通行不可からコスト+40に変え、前方の再検査では生物を見なくした。隙間に立つ牛・横切る牛の試験が成功するようになった（02のA1「実施結果」）。
3. **葉を「破壊できる障害物」として扱う**（05）。**2026-10-26に実施済み**（07）。視線を遮っているのが葉だけなら、届く範囲の葉を掘ってから原木を掘る。届く距離は目から4.5で測る。
4. **反射層 `NpcReflexes` を追加する**（04）。**最小構成（反撃・溶岩/火からの退避）を2026-10-26に実施済み**。毎Tick、計画とは独立に「被弾→反撃」「溶岩・火→退避」「低体力→食事・後退」を実行し、実行中の技能を一時停止する。
5. **指示を捨てる規則を直し、LLMの往復を1回にする**（04）。**指示を捨てる規則は2026-10-26に修正済み**。往復の削減は後続。定型文での即時処理は誤動作の恐れがあるため採用しない。
6. **move_toの終点許容と途中経路の利用**（02）。**終点の許容（A5）は2026-10-26に実施済み**。同日、03のB5（横移動の誤発火）も修正した。途中経路の利用（A8）も実施済み。探索予算切れでも、目標に最も近いノードまでの経路を使って進む。
7. **WaterStateの導入**（05）。目が水中か、足下の深さ、水面までの距離、水面上が空気か、最寄りの空気と岸を1つの状態にまとめる。
8. **構造の整理**（01）。NavigationService、WorldModel、ReflexLayerへ責務を分ける。`NpcSkills`（2,254行）を分割する。

1〜3は現在の試験基盤（GameTest 121〜130件）ですぐに効果を測れる。4〜5は操作感への影響が最も大きい。

定型文（キーワード）による指示の即時処理は、誤動作の恐れがあるため修正案から外した（2026-10-26、利用者の判断）。指示の解釈は引き続きLLMが行う。
