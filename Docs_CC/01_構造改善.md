# 01 MOD構造の改善

## 現在の構造

```text
ServerChatEvent → NpcChatRouter → NpcMind.hearPlayer
                                   ↓ 会話LLM 1往復（speech / instruction）
CompanionEntity.setInstruction → NpcMind.stop()（全セッション閉鎖・チャット破棄）
                                   ↓ 新規セッション + 計画LLM 1往復（TaskPlan）
LocalTaskRunner.tick（毎Tick: 観察→候補8個→学習モデルで順位付け→NpcSkills.execute）
                                   ↓ pending中は何もしない
NpcSkills.tick（長い技能を1つだけ実行。優先順: farming > interactions > longTravel
                > construction > areaWork > workRoute > acquisition > smelting
                > expedition > 単発 > following）

CompanionEntity.tick: waterSafety.preTick → super.tick（Float/Door/LookAtのGoalのみ）
                      → vitals → if (!waterSafety.tick()) mind().tick()
```

### 構造上の問題

1. **反応の層が1つしかない。** LLMの計画から技能の実行まで、すべてが直列につながっている。毎Tick計画と無関係に動く処理は `NpcWaterSafety` だけ。戦闘・溶岩・落下・低体力への反応は「学習モデルが選ぶ候補の1つ」で、`LocalTaskRunner` が `pending` の間は評価されない（`LocalTaskRunner.java:250`）。
2. **経路・到達判定が複数ある。** 同じ「そこへ行けるか／そこから操作できるか」を、以下がそれぞれ別の基準で判定している。
   - `NpcWalkSurface.standable`（衝突形状で支持を判定。葉を足場として認める）
   - `NpcLocalWorld.approach`（`isFaceSturdy(UP)`。葉を足場として認めない。dyは-1〜+1）
   - `NpcWorkRoute.stable / ready / harmful`（流体を全面禁止。中心の1本の視線）
   - `NpcSkills.visibleHitFrom`（7点の視線。足元からの距離）
   - `NpcExpedition` と `dig` の接近は旧来の `createPath`

   既存資料（`NpcArchitectureReview20261025.md` の NavigationService 案）でも指摘済み。候補生成では「到達可能」なのに実行時は「不可」になる不一致の主な原因になっている。
3. **巨大クラス。** `NpcSkills.java` 2,254行、`LocalTaskRunner` 1,159行、`NpcLocalWorld` 1,153行、`NpcMind` 961行。移動・採掘・観察・戦闘・水泳が同じクラスにあり、変更の影響範囲を追いにくい。`waterWalking`（`NpcSkills.java:1373`）のように呼ばれていない処理も残っている。
4. **試験コードが製品のソースセットにある。** `src/npc` 内に GameTest 25ファイル・約9,300行（全体の約30%）がある。`avatarcraft.npcGameTest` で登録を切り替えているが、配布JARには含まれる。
5. **ai パッケージに85ファイルが平置きされている。** 技能・知覚・経路・LLM接続・試験が同じ階層にある。
6. **LLMの要求枠がサーバー全体で1つ。** `NpcService.requestSlot` は全NPCの会話・計画・定期発言で共有され、3秒間隔（`CodexConfig.java:25`）。指示の処理が雑談の発言に待たされる。

## 提案する構成

```text
┌ L2 戦略層（非同期、数秒〜数十秒）─────────────────────────┐
│ LLM: 指示の解釈 → TaskPlan / Goal。1指示につき1往復が目標   │
│ 検証済み計画のキャッシュはL1へ直接渡す                      │
└──────────────┬──────────────────────────────────────────┘
               ↓ Goal（型付き・完了条件付き）
┌ L1 戦術層（毎Tick、中断・再開できる）──────────────────────┐
│ TaskGraph / LocalTaskRunner: 段階、候補生成、学習モデルで選択 │
│ ローカル再計画: 別の対象・別の立ち位置・別の経路を先に試す    │
│ Skill: 実行中にinterruptRequested()を毎Tick確認する          │
└──────────────┬──────────────────────────────────────────┘
               ↑ pause / resume
┌ L0 反射層（毎Tick、ルールのみ、モデルを呼ばない）───────────┐
│ 溺水（既存）・被弾反撃・所有者防衛・溶岩/火・落下・低体力・  │
│ クリーパー回避・矢の回避                                    │
└──────────────────────────────────────────────────────────┘
     ↕ 共有
┌ WorldModel（知覚の唯一の情報源）──────────────────────────┐
│ VoxelGrid: solid / soft_breakable / fluid_shallow /        │
│            fluid_deep / air / unknown                      │
│ WaterState・EntityTracks・Resources（到達コスト付き）       │
└──────────────────────────────────────────────────────────┘
     ↕
┌ NavigationService ────────────────────────────────────────┐
│ 1つのA*、1つの立てる判定、1つの「操作できる位置」判定       │
│ 歩行・作業経路・追従・接近・水泳が同じグラフを使う          │
└──────────────────────────────────────────────────────────┘
```

### 各層の責務と既存コードの移行先

| 新しい部分 | 責務 | 既存コードから移すもの |
| --- | --- | --- |
| `NpcReflexes`（新規） | 毎Tickのルール判断。発火したら技能を一時停止し、終わったら再開する | `NpcWaterSafety`、`NpcLocalWorld.tactics`（防御）、`eat` の候補、`NpcExpedition` の撤退条件 |
| `NavigationService` | 経路探索、立てる判定、接近位置、経路の再利用、詰まり検出 | `WalkingPathSearch`、`NpcWalkingRoute`、`NpcGroundNavigation`、`NpcWalkSurface`、`NpcLocalWorld.approach`、`NpcWorkRoute` の到達判定、`NpcFollowing` の目標生成 |
| `WorldModel` | 周囲のボクセル分類、水の状態、生物の軌跡、資源と到達コスト | `NpcSpatialObservation`、`NpcObservations`、`find_blocks`、`NpcWaterTravel.column` |
| `SkillExecutor` | 技能ごとのクラス（Move、Mine、Fell、Swim、Combat…）。共通の `tick / pause / resume / cancel` | `NpcSkills` を分割する |
| `RequestScheduler` | LLM要求の優先度（所有者の指示 > 計画 > 復旧 > 定期発言） | `NpcService.requestSlot` |

GameTestは `src/npcTest`（新しいソースセット）へ移し、`npcJar` から外す。`build.gradle` の `runs` にある GameTest 用の起動構成だけがそれを参照するようにする。

**2026-10-26に実施済み**。ソースセット名は `npcGameTest`（`src/npcGameTest/java`）。開発時の起動では同じMODとして読み込み、配布JARには含めない。登録はリフレクションで行う。詳細は08。

## 移行の順序（全面書き換えをしない）

1. **反射層を先に足す。** `CompanionEntity.tick` の `waterSafety.tick()` の隣に置く。既存の構造を変えずに効果が出る。
2. **NavigationServiceに「立てる判定」と「接近位置」を1つにまとめる。** まず `NpcLocalWorld.approach` と `NpcWorkRoute.ready` を、`NpcWalkSurface` の判定を呼ぶように置き換える。
3. **技能に中断機能を付ける。** `NpcSkills` の長い技能（ToolQueue、LongTravel、Construction、Expedition）に `interruptRequested()` を確認させる。
4. **NpcSkillsを技能ごとのクラスへ分割する。** 1技能ずつ移し、既存のGameTestで回帰を確認する。
5. **WorldModelへ観察を集約する。** 計画用の観測（`NpcObservations.planning`）もここから作る。

既存資料の「Goal / TaskGraph」「WorldMemory」「RecoveryController」の提案（`Docs/NpcArchitectureReview20261025.md`）とは矛盾しない。本資料はそれに反射層と知覚の統一を加えたもの。定型文による指示の即時処理は、誤動作の恐れがあるため採用しない。
