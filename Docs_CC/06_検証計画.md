# 06 検証計画

## 追加するGameTest

既存の試験（GameTest 121〜130件）は、平坦な地形や配置した資源での成功を主に見ている。今回の4課題を検出できる試験を追加する。

### 経路・移動

| 試験 | 合格条件 |
| --- | --- |
| 実速度の計測 | 平地20ブロックの歩行・ダッシュの秒速がプレイヤーの実測値の±10%以内 |
| 所有者が終点に立っている | 所有者の隣まで移動できる（UNREACHABLEにならない） |
| 牛・羊が経路を横切る | 再探索が2回以下で到着する |
| 2〜3ブロックの段差を下りる | 迂回せずに飛び降りる |
| はしごで上る | 5段のはしごで上の階へ |
| 岸の深さ1の水を渡る | 浅瀬を歩いて渡る |
| 幅1の通路・壁沿い | 平地の90%以上の速度で移動する |
| Yを1ずらした目標 | 隣の立てるセルへ到着する |
| 探索予算を超える迷路 | 部分経路で進み続け、最終的に到着する |
| 追従：所有者が階段・ハーフブロック上 | 2ブロック以内を維持する |

### 即時反応・指示

| 試験 | 合格条件 |
| --- | --- |
| 長い作業（area_work）中にゾンビに攻撃される | 2Tick以内に反撃を開始し、倒した後に作業を再開する |
| 指示なしで待機中に攻撃される | 反撃する |
| 所有者が攻撃される | 攻撃した敵を狙う |
| 溶岩の隣で足を滑らせる | 安全なブロックへ退避する |
| クリーパーが着火 | 爆発範囲外へ離れる |
| 「止まって」 | LLM1往復で停止する（モック脳で要求1件を確認） |
| 「ついてきて」→作業依頼→完了 | 完了後に追従が戻る |
| 指示の直後に「急いで」 | 指示が失われない |
| 返答待ちの間にプレイヤーが13ブロック離れる | 指示が実行される |
| 2体が同時に発言・計画 | 所有者の指示が定期発言に待たされない |

### 周辺認識

| 試験 | 合格条件 |
| --- | --- |
| 樹冠が幹のY+3〜+6を囲む木 | 葉を除いて原木を全数回収する |
| 大きなオーク・ジャングルの木（自然生成） | 下の原木から順に回収する |
| マングローブ・湿地の木 | 水に接していても掘る（流れ込まない場合） |
| 深さ7の水に沈んだ状態 | `reachable` が空でなく、岸へ泳ぐ |
| 氷の張った池に落ちる | 天井を認識し、穴か岸へ向かう |
| 水面すれすれ（目のY−0.1） | 空気の減少とWaterStateの判定が一致する |
| プール上の離れた足場（`NpcWaterPoolStudy` の再試験） | 入水して渡るか、所持する板材で橋を架ける |

## 計測指標

既存資料の方針と同じく、試験の成功と一般的な実プレイの成功は分けて扱う。

| 指標 | 取り方 |
| --- | --- |
| 移動の実速度（ブロック/秒） | 移動中の `horizontalDistance*20` の中央値 |
| ダッシュの割合 | 移動Tickのうち `isSprinting` の割合 |
| `UNREACHABLE` の件数と理由の内訳 | 終点不正 / 生物で閉塞 / 予算切れ / 本当に経路なし |
| 1回の移動の停止回数 | `navigation.stop` と `SEARCHING` で静止したTick |
| 被弾から反撃までのTick | `hurtServer` から最初の `attack` まで |
| 指示から最初の行動までの時間 | `instruction` から最初の `tool_start` まで |
| 1指示あたりのLLM要求数 | 1が目標（キャッシュ済みの計画は0） |
| 捨てられた指示の数 | 新しい `instruction_dropped` イベントで、捨てた理由を記録する |
| 樹冠内の原木の回収率 | 試験の木の原木の総数に対する回収数 |
| サーバーのMSPT p95 | 順位付けモデル・経路探索の負荷 |

## 実施の順序

各段階で、既存のGameTest全件と、同じ5 seed（61279〜61283）の自然地形試験を回す。5 seedの結果は以前のv7の結果（`Docs/NpcV7FiveTaskVerification20261026.md`）と比べる。

1. **移動の実測**（B1の数値を確定させる）→ 速度の換算の修正 → 再計測
2. 経路探索から生物を外す、終点を集合にする、中継点の判定を直す
3. 葉を考慮した視線判定、目からの届く距離、葉の除去
4. 反射層
5. 指示を捨てる規則の修正、要求の優先度
6. WaterState、浅瀬、部分経路、落下・はしごの辺
7. 構造の整理（NavigationService / WorldModel / NpcSkillsの分割、GameTestのソースセット分離）

1〜3は変更が小さく、5 seedの「原木64収納」「石炭64収納」の改善で効果を確認しやすい。v7の失敗の多くは原木の調達と `No supported walking route` で止まっていた。

## ログに追加する項目

- 移動: 経路の開始・終点候補の数・ノード数・探索時間・打ち切りの理由・閉塞の原因（生物か地形か）・実速度
- 反射: `reflex_start` / `reflex_end`、種類、一時停止した技能
- 指示: 受信時刻、LLMへ送った時刻、計画の受信時刻、捨てた理由
- 採掘: 遮っていた葉の数、除去した葉の数、目からの距離
- 水: WaterState（10Tickごと）
