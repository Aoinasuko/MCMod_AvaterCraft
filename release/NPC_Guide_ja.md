# AIアバターNPCの導入と開発

Minecraft 26.3、NeoForge 26.3.0.95、Java 25向けです。NPCのゲーム処理はサーバーで動作します。

## 導入

- NPCを使うクライアントとサーバーの両方へ `avatarcraft-0.6.0.jar` と `avatarcraft-npc-0.6.0.jar` を配置します。プレイヤーのアバター表示だけを使う場合はFrameworkのJARだけで利用できます。
- 標準アバター「タートブ」（作者：aoi_nasuko）と性格プリセットをNPC用JARに同梱します。クライアント起動時に `config/avatarcraft/avatars/tortobu.avc` がない場合だけ展開します。同名の既存ファイルは上書きしません。
- 追加モデルは、表示する各クライアントの `config/avatarcraft/avatars/` に使用権のある `.avc` を配置します。NPC用の追加モデルのネットワーク自動配布は行いません。0.6.0の表示専用プレイヤーキャッシュをNPCの外見に流用することもできません。
- 手元の追加モデルは外部 `.avc` として追加し、性格JSONの `avatar` にアバターIDまたは拡張子を除いたファイル名を指定します。IDの一致を優先します。

## AIの接続設定

Mods → AvatarCraft AI Companions → 設定 → Local の `ai` を開きます。設定ファイルは `config/avatarcraftnpc-ai.toml` です。変更後はワールド／サーバーを開き直してください。マルチプレイではサーバーを実行する環境の設定を使います。クライアント側のキーはサーバーへ送信しません。旧 `config/avatarcraftnpc/codex.json` は使用しません。

| 接続方式 | provider | baseUrl | model | apiKeyEnvironment |
| --- | --- | --- | --- | --- |
| Codex CLI OAuth | CODEX | 未使用 | 空文字でCLIの既定値 | 未使用 |
| OpenAI API | OPENAI | `https://api.openai.com/v1` | 利用可能なChat Completions対応モデルID | `OPENAI_API_KEY` |
| LM Studio | OPENAI | `http://localhost:1234/v1` | ロードしたモデルID | 認証不要なら空文字 |
| Ollama | OPENAI | `http://localhost:11434/v1` | インストールしたモデルID | 認証不要なら空文字 |
| Anthropic互換 | ANTHROPIC | `https://api.anthropic.com/v1` または互換サーバーのベースURL | 利用可能なMessages対応モデルID | `ANTHROPIC_API_KEY` |

LM Studio・Ollamaでは関数ツール呼び出しとJSON出力に対応するモデルを使用してください。モデルを自動でダウンロード・起動する機能はありません。`baseUrl` には `/chat/completions` や `/messages` を付けず、`/v1` までを指定します。接続先により対応API・ツール呼び出し精度は異なります。

APIキーは `apiKeyEnvironment` で指定した環境変数を優先します。空または未設定なら `apiKey` の値を使います。ローカルサーバーでキーを使わない場合は両方を空文字にします。`apiKey` に直接入力した値はローカルTOMLに平文で保存されるため、キー入りの設定ファイルを配布しないでください。設定ファイル、キー、認証情報をNPCの性格JSONや記録には保存しません。

```toml
[ai]
enabled = true
provider = "OPENAI"
model = "your-tool-capable-model-id"
baseUrl = "http://localhost:1234/v1"
apiKeyEnvironment = ""
apiKey = ""
requestTimeoutSeconds = 30
turnTimeoutSeconds = 180
maxToolCalls = 32
maxConcurrentTurns = 3
minimumRequestIntervalSeconds = 3
maxOutputTokens = 4096
```

HTTP接続はサーバースレッドの外で実行し、総ターン時間・応答サイズ・コンテキスト・ツール回数を制限します。発言用の同時実行枠を1つ確保します。停止や指示変更で古い処理を破棄し、HTTPエラー本文やAPIキーをゲーム内の記録へ出しません。プロバイダーのHTTPエラーに対して自動再送して重複操作する処理はありません。

### Codex OAuthを使う場合

この接続だけはAPIキー不要です。ホスト環境でCodex CLIを用意し、ユーザー自身が `codex login` でChatGPTにログインします。`codex login status` で確認し、`provider = "CODEX"` にします。PATHにCLIがない場合は `codexExecutable` にパスを設定します。`model` が空文字ならCodexの既定値を使います。

[Codex App Server](https://learn.chatgpt.com/docs/app-server)の動的ツールは実験的APIであり、検証したCLIは0.163.0です。更新時は互換性を確認してください。認証は[公式認証ガイド](https://learn.chatgpt.com/docs/auth)を参照してください。

### HTTP方式の参照仕様

- [OpenAI Function calling](https://developers.openai.com/api/docs/guides/function-calling)：Chat Completionsの `tool_calls` と `tool_call_id`。
- [Anthropic Tool calls](https://platform.claude.com/docs/en/agents-and-tools/tool-use/handle-tool-calls)：Messagesの `tool_use` と `tool_result`。
- [LM Studio Tool Use](https://lmstudio.ai/docs/developer/openai-compat/tools)。
- [Ollama OpenAI compatibility](https://docs.ollama.com/api/openai-compatibility)。

## 召喚石と記録帳

作業台で次の配置を使います。

```text
I G I
G G G
I G I
```

Iは鉄インゴット（計4個）、Gは金インゴット（計5個）です。ソウルストーンを1個作成します。共通アイテム「ソウルストーン」を持って地面へ使用すると1つ消費し、標準のタートブを召喚します。モデルと性格は召喚後のGUIで変更できます。衝突する場所へは召喚しません。所有者は召喚したプレイヤーです。

作業台で中央に本1冊、周囲8マスに鉄インゴット8個を配置すると「アバターの記録帳」になります。持って使用し、記録のあるNPCを切り替えて閲覧できます。所有者の記録だけを表示します。NPCが復帰中・未ロードの場合も保存済みの記録は閲覧できます。専用テクスチャは`memory_journal.png`です。

## アバターアンカー（共有の場所ID）

作業台で任意の板材1個を鉄インゴット8個で囲むと、アバターアンカーを1個作れます。クリエイティブでは道具タブにも表示します。石以上のツルハシで回収できます。

```text
I I I
I P I
I I I
```

Iは鉄インゴット、Pは任意の板材です。設置後に右クリックし、32文字以内のIDを入力して「保存」を押します。日本語と英語を使えます。IDはワールド全体で一意で、別の設置地点と同じIDは保存できません。空欄で保存すると解除でき、ブロックを壊した場合も登録を解除します。通常のブロック操作が許可されているプレイヤーがその場で編集できます。

IDは所有者に関係なくすべてのNPCが参照でき、NPC個別の場所記憶8枠は消費しません。例えばIDを「拠点の倉庫」として保存し、NPCへ「拠点の倉庫のチェストに持っているアイテムをすべて収納して」と指示します。NPCはそこへ移動し、アンカーから8ブロック以内の操作可能なチェストを使用します。複数あれば空き容量を確認し、満杯なら範囲内の別のチェストを試します。アンカー自体に収納機能はなく、別の拠点のチェストへ勝手に切り替えません。名前での移動や、その周囲のチェストからの取り出しにも使えます。

同名の個人記憶がある場合は共有アンカーを優先します。ID・座標・ディメンジョンはワールドに保存し、未ロードでも場所情報は残ります。アンカーを登録するだけで周囲を常時読み込みしたり、NPCをテレポートしたりはしません。歩行は既存の最大512ブロックの移動予約と経路・チャンクの条件に従い、別ディメンジョンでは実在のポータルを通る計画が必要です。

## 死亡・呼び戻し・召喚上限

NPCが倒れると現在の作業・委任・追従を中断し、通常はバッグと装備を死亡した位置へ落とします。約20Tick後に所有者のリスポーン地点へ復帰し、その位置で待機します。作業や追従は自動再開しません。ベッド等が使えない場合はバニラの復帰先判定に従い、安全な場所を探します。リスポーンアンカーのチャージは消費しません。所有者がオフラインの場合は保存済みの復帰位置を使い、使えない場合はワールドの復帰地点へ戻します。

「呼び戻しの地図」は、作業台の中央に空の地図1枚、周囲8マスに鉄インゴット8個で作成します。専用テクスチャは`recall_map.png`です。手に持って使用すると、自分が召喚中のNPC一覧を表示します。呼びたいNPCのボタンを押すと、別ディメンジョンからでもプレイヤーの近くへ移し、作業と追従を解除して待機させます。地図は消費しません。未ロードのNPCは一時的にチャンクを読み込み、最大200Tick待ちます。処理中は地図を手に持っていてください。安全な着地点がない場合や対象を読み込めない場合は理由を表示します。他人のNPCは一覧にも表示せず、呼び戻しもできません。

設定はサーバー／ホスト側の`config/avatarcraftnpc-server.toml`です。NeoForgeのSynced設定として接続中のクライアントへ同期します。ワールド別に上書きする場合は、そのワールドの`syncedconfig/avatarcraftnpc-server.toml`を使います。

```toml
[companions]
maxPerPlayer = 3
dropItemsOnDeath = true
```

`maxPerPlayer`は1人の所有者が召喚できる最大数です。既定3、`-1`で無制限、`0`で新規召喚を禁止します。全ディメンジョン・未ロード・復帰中のNPCを保存台帳で数え、サーバーが判定します。上限を下げても既存NPCを削除せず、新規召喚を制限します。クライアント側の設定でサーバーの上限を回避できません。`dropItemsOnDeath=false`ならバッグ・主手・副手・防具を持ったまま復帰します。

通常のNPC会話は、同じディメンジョンでNPCから半径64ブロック以内のプレイヤーだけに表示します。死亡・作業保留・追従先の不在や経路不明等の重要通知は、専用フラグで所有者だけへ送り、所有者の距離やディメンジョンを問いません。オフライン中のチャット通知を後で自動配信する機能はありません。

## 右クリック画面

右端のアイコンだけのボタンで4つのメニューを切り替えます。ホバーすると黄色の名前と灰色の説明が表示されます。小さいウィンドウでは全体を縮小し、スロットとクリック位置も同じ倍率に合わせます。

- 持ち物：上部にアバター・バニラの体力／空腹アイコン・防具4枠・主手／副手・NPCのバッグ36枠、下部にプレイヤーの持ち物とツールバーを同時表示します。通常クリック・Shiftクリックで受け渡せます。主手と副手へ直接アイテムを置いて装備できます。所有者以外は開けず、NPCから離れると閉じます。
- 性格・外見：JSONを編集して保存します。矢印でローカルのアバターを選ぶとJSONへ反映します。性格ボタンでプリセットを切り替えられ、選択中のモデルを保持します。変更後に「保存・実行」を押します。「一覧再読込」は更新した `.avc` を読み直します。
- 作業指示：日本語で具体的な作業を入力して「保存・実行」を押します。「作業停止」で作業の移動・操作・推論を止めます。待機中の自動追従は「追従: ON/OFF」で切り替えます。指示の変更でも古い推論結果を破棄します。
- 記録：会話、指示、ツール実行結果を新しい順に表示します。「過去の記録」で以前のページ、矢印でページ内を送れます。

性格には `id`、`name`、`avatar`、`instructions`、`speakingStyle`、`goal`、`allowedSkills`、`workSpeechSeconds`、`nearbyConversationSeconds` を設定します。定期発言の `workSpeechSeconds` は30〜60秒、既定の性格は45秒です。`nearbyConversationSeconds` はNPC同士で会話相手を選ぶ間隔で15〜3600秒です。JSONの許可スキルに未知の名前は指定できません。

追加の性格プリセットは、ホスト環境の `config/avatarcraftnpc/personalities/<id>.json` に配置します。GUIを開き直すと既定のタートブと有効な外部プリセットを最大12件読み込みます。ファイル名とJSONの `id` を一致させ、1ファイル16KiB以下にしてください。現在の性格JSONをコピーして `id`・`name`・`avatar`・話し方などを変更できます。追加モデルは各クライアントに別途必要です。

## 近くのプレイヤーとの会話

同じ次元で12ブロック以内、視線の通るNPCは通常チャットに応答します。名前を含めると該当NPCへ、指定がなければ最も近い所有NPCを優先して届けます。「二人とも」「みんな」「全員」などの呼びかけや複数の名前では最大4体へ届けます。

所有者の具体的な依頼をAIが作業指示と判断すると、GUIを開かずに作業を開始します。「作業を止めて」といった停止指示にも対応します。挨拶や質問には会話で応じ、所有者以外の発言から作業指示を変更しません。応答までに離れた場合や所有者・指示が変わった場合は古い結果を適用しません。AIの応答時間や指示の解釈により開始まで時間がかかる場合があります。

## 行動と保存

日本語・英語の新しい指示は、選択中のAIが共通タスクへ変換します。以降の通常の行動は、同梱した約20MiBの学習済みモデルが候補を評価して選び、サーバー側で実行します。利用者によるPython・GPU・追加のローカル推論サーバーの導入は不要です。指示理解と発言のAIには行動ツールを与えません。「少し」「不足分」「いつもの場所」などは、観察・場所の記憶・前の進捗から補える範囲で解釈します。参照先を特定できない場合は、確認が必要な理由を返します。詳しい構成・学習手順は [ローカル行動モデル](NPC_LocalAI_ja.md) を参照してください。

ゲーム操作は従来の移動・採掘・工作・収納等に、精錬・委任・照準・狩猟・アイテム使用・ポータル通過・構造物探索・掘削と設置を伴う作業経路等を加えた全52種です。[ツール一覧](NPC_Tools_ja.md) に追加／既存の区分、正確な引数、実行条件、成功判定をまとめています。許可スキル、実際の持ち物、距離、所有者の権限等を検証して実行します。失敗は完了扱いにせず、最大2回までAIに再計画を依頼し、それでも実行できない場合は理由付きで保留します。

「原木を集めて」は葉の除去や高木への足場を必要に応じて行います。「ブロックを掘ってこっちに来て」「こっちまで橋を架けて」では観察済みの目的地まで掘削・架橋し、実際に移動します。足場には土・丸石等を使用します。掘削を禁止した場合は持ち込んだ建材が必要です。詳しい予算・範囲は [障害物・足場・橋](NPC_LocalAI_ja.md#障害物足場橋) を参照してください。

各NPCは最大8件の名前付きの場所を記憶します。近くのアクセス可能なチェストを自動的に覚え、`remember_location`／`forget_location` で名前を指定して記憶・忘却できます（`observe` の権限でも利用可能）。「このチェストを拠点として覚えて」「回収地点のアイテムを拾い、拠点へ戻して」等の依頼に使用します。次元・座標・種類はNBTへ保存し、出発時の収納先を固定して帰還します。満杯での自動削除や、別次元へのテレポートは行いません。

鉱石が見つからない場合は移動・階段状の掘り下げへ進み、通常鉱石と深層鉱石を同じ資源として探します。現在の足元、経路の支え、液体、崩落、保護などを確認し、安全に進める候補がない場合や探索の上限では理由を示して保留します。`acquire`は空の持ち物から実資源を集め、木・石・鉄の道具や設備を作り、通常かまどで精錬します。

同じ所有者の近くのNPCへ、リーダーが資材準備や探索の担当を割り当てます。実物の受け渡しと保存した担当状態を使い、要求された最終数量を人数分重複させません。NPCのいるチャンクと周囲1チャンク（3×3）は常時Tick読み込みします。移動・削除に追従してチケットを更新します。

協力・ネザー・エンド等の長い依頼は上位モデルで計画します。設定の`ai.complexModel`へ同じ接続先の高性能モデルIDを指定します。空なら通常モデル、Codex方式では上位計画のreasoning effortをhighにします。最大24手順の段階を検証済みの進捗からつなぎ、最大64段階で止めます。完全自律で新規ワールドからドラゴン討伐まで完走する試験は未実施です。GUI取引・エンチャント・金床・任意の乗物操縦等は網羅していません。

例：「周囲を確認して、近くの原木を1つ掘り、板材を作ってください」「近くの敵を攻撃してください」「私についてきてください」。道具・材料・収納先の座標等が必要な作業では、持ち物を渡して具体的に指示してください。ブロック検索は読み込まれた範囲で半径16、移動先は64ブロック以内です。収納・設置等には距離と視線の確認があります。クラフトは登録済みの作業台レシピを使い、大きなレシピには近くの作業台が必要です。アイテムを生成して材料を補いません。

`equip(slot, hand)` はバッグ0〜35と `main`／`off` の手を丸ごと交換します。空のバッグ枠を指定すると手に持つアイテムを戻せます。食事中は持ち替えを拒否します。観察結果はバッグ・防具・主手41・副手40を区別します。

`find_chests(radius)` で半径1〜16のチェスト位置と中身のスロット番号を調べ、4ブロック以内に近づいて `deposit(x,y,z,slot,count)` でバッグから収納、`withdraw(x,y,z,slot,count)` でチェストから取り出します。`give_item(entity_id,slot,count)` は4ブロック以内で見える別NPC・プレイヤーへバッグのアイテムを渡します。1回1〜64個で、受け入れられた個数だけを元の持ち物から減らし、余りは元の場所に残します。ロック・保護・塞がれたチェストは操作しません。ダブルチェストでは両側のロックを確認します。

チェスト・樽・シュルカーボックスは、収納・取り出し・右クリック時にバニラの開閉アニメーションと音を再生します。15Tick（通常速度で約0.75秒）開いてから実際の操作を行い、その後に閉じます。プレイヤーや別のNPCが利用中なら、その人の分まで閉じません。途中停止・撤去等では未実行のアイテム移動を取り消します。観察・一覧取得だけでは開きません。エンダーチェストの右クリックも開閉しますが、所有者の専用インベントリの中身は操作しません。

作業中の遠い移動や採掘・回収先への接近は、8ブロック以上でダッシュし、4.5ブロック未満で歩行へ戻ります。空腹6以下、水中、スニーク中等は走りません。経路の段差や狭い通路でも歩行へ戻ります。ドロップ回収や設備への最終接近の`move_precisely`は精度を優先して歩きます。到着・停止時はダッシュを解除します。

待機中の自動追従は6ブロックを超えると開始、2.5ブロック以内で停止します。8ブロックを超えるとダッシュし、4.5ブロック以内で歩行へ戻します。見通しが一時的に遮られても経路探索を続けます。作業中は指定した行動を優先します。自動追従によるテレポートや次元移動は行いません。計画中の`travel_dimension`は実ポータルを使います。

開発中の持ち物形式を変更しているため旧NPCの所持品との互換性はありません。新しく召喚したNPCで利用してください。性格の `allowedSkills` を個別に制限する場合は、必要な新スキルも追加してください。

体力20、攻撃・移動等はPlayerの属性を基準にし、装備と空腹・満腹度・消耗・自然回復・飢餓を扱います。戦闘は通常の装備属性を使い、敵対Mob・ボス等を攻撃します。`hunt`では食料・素材の狩猟も行います。プレイヤーやペット等は対象にしません。採掘は道具の速度・耐久・通常のドロップを使います。所有者が切断すると作業を止めます。

近くのNPC同士は視線と距離を確認して会話します。待機中も含めて30〜60秒（既定45秒）ごとに、観察・検証済みの作業進捗・最近の会話から発言を生成します。プレイヤーから話しかけられたときの応答は別に扱います。発言の生成待ちやAPI接続の失敗で、取得済みの計画に沿ったローカル作業を止めません。発言はAIの応答時間や利用制限の影響を受けるため、表示までの時間を保証するものではありません。ワールドが一時停止している間はゲーム時間も進みません。

所持品・装備・性格・所有者・アバター・指示・空腹状態・ローカル作業の残り手順をエンティティとともに保存します。切断時は作業を止め、再接続時は残りの作業を再開します。収納等で既に移動した個数は残数から差し引きます。会話と行動ログは各ワールドの `avatarcraftnpc/journal/<owner-uuid>/<npc-uuid>/` にJSONLで保存します。8MiB単位に分割し、過去ログを自動削除しません。バックアップにはこのフォルダも含めてください。

## Framework API

共通MODの `dev.avatarcraft.api` は、クライアントに依存しない `AvatarActor`、`AvatarCatalog`、`AvatarAnimation` を提供します。Mobへ `AvatarActor` を実装し、CLIENT限定の登録処理で `AvatarActorRenderer` を登録すると、独立した表情・モーション・物理状態で描画できます。`avatarMining()` は採掘モーションの指定用です。クライアントの描画APIを専用サーバーの初期化コードから呼び出さないでください。

NPCの防具・頭装備・エリトラのモデルは描画しません。装備スロット、性能、耐久は通常どおり扱い、アバター本来の衣装を表示します。

lilToonの不透明・カットアウト・半透明モード、色のalpha、AlphaMaskの置換・乗算・加算・減算、UV、深度書込を描画に反映します。半透明は距離順に並べますが、重なり合う面や複数素材の順序はUnityと完全には一致しません。法線2層・MatCap2層・メイン2／3層目・色調補正・影／リム／発光／輪郭／ディゾルブのマスクにも対応します。新しい素材情報を使うには更新したUnityツールで再変換してください。詳しくは `LilToon_ja.md` を参照してください。VRChatのAnimator FX、Expression Menuや実行時スクリプトは動かしません。詳細はアバター設定ガイドを参照してください。

## 自動検証

`tools/dev.ps1 -Task build` はユニットテストを含みます。`-Task runNpcGameTest` は独立した検証ワールドで、召喚・上下インベントリ配置・防具・保存・採掘・設置・クラフト・収納・取り出し・NPC／プレイヤーへの受け渡し・満杯時の保存・食事・ダッシュ追従・記録を検証します。OAuthの実接続テストは `AVATARCRAFT_CODEX_LIVE=1` を明示して `-Task test` を実行した場合だけ有効になります。実接続テストはCodexの利用枠を使います。

HTTP方式はローカルの模擬APIで両プロトコル・ツール往復・停止・許可検証・重複呼び出し抑止・HTTPエラー処理を検証します。実サービスのキーやユーザー環境のモデルを使った接続結果は含みません。
