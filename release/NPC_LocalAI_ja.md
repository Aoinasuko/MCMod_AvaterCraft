# NPCのローカル行動モデルと場所の記憶

## 実行記憶と復旧予約

失敗した対象、資源やチェストの検索結果、実際に歩いた道、確認済みの完了結果をNPCごとに保存し、親子のタスクで共有します。同じ状況の失敗を繰り返さず、地形・道具・立ち位置が変化した場合や待機期間が過ぎた場合は再評価します。足場資材の調達中は、さらに足場資材が必要な経路を再帰的に作りません。近くの同じ所有者のNPCは検索結果も参照できます。

チェストへの通常移動は周囲の立てる位置へ向かいます。地下からの帰還は実際に歩いた階段や既存の歩行経路を優先します。編集する経路の上下制限は各区間で維持するため、必要な場合は中継点を設けます。

通常の再計画でも停止が続く場合、設定中の外部AIへ3〜5手の短い復旧予約を要求します。予約も通常の権限・引数・所持品の検証を通し、一つずつ実行します。予約を終えたら元の目標と残作業へ戻り、予約だけの終了を依頼全体の完了とは扱いません。予約要求は1つの依頼で最大2回。状況が改善せず上限に達した場合は理由を通知して保留します。

目標の作業が検証済みで完了すると、直ちに追従を解除して待機へ戻ります。達成の通知は確認済みの結果だけを渡し、性格の`instructions`と`speakingStyle`に合わせた短いセリフとして一度生成します。発言用AIは操作や達成判定を行いません。完了前の状況で生成中だった古い発言は破棄します。

性格JSONに任意の`completionMessage`（512文字以内）を指定すると、そのキャラクター用の文を生成せずに通知します。空の場合はAI生成を使い、接続失敗・応答なし・未確認とする誤った返答では完了確認済みの短い代替文を使います。タートブには口調に合う代替文があります。発言の待ち時間で、完了や待機への移行を遅らせません。

周囲の看板は`read_signs`で読めます。ロード済み・見える立て看板、壁看板、吊り看板の表裏、座標、向きを取得し、計画時にも付近の表示を参照します。看板の文章は環境の情報として扱い、所有者の指示・権限を上書きしたり、看板のクリックコマンドを実行したりしません。

## 構成

日本語・英語の依頼は、設定中のCodex／OpenAI互換／Anthropic互換AIが共通タスクへ変換します。実行可能な候補が複数ある場合、MODに同梱した約20MiBの学習済みモデルで選びます。候補が1つの場合や進行確認は直接処理し、ツールの可否・安全条件はサーバー側で検証します。利用時にPython・GPU・ローカルAIサービスを追加する必要はありません。

発言は行動と分離し、30〜60秒ごとに現在の状況と検証済みの進捗から生成します。性格の `workSpeechSeconds` の既定値は45秒です。発言の応答待ちや接続失敗で、取得済みの計画に沿ったローカル作業を止めません。新規依頼の理解と失敗後の再計画には、設定したAIへの接続が必要です。

計画は最大24手順・16KiBです。操作・型・数量・座標を検証し、実際の持ち物と所有者の権限を使って実行します。道具・材料・ドロップを生成して補うことはありません。失敗時の再計画は最大2回とし、実行できない理由を表示します。

## 探索と地下採掘

鉱石を探して見つからなかった場合は、移動や掘り下げの候補を選びます。通常鉱石・深層鉱石は同じ資源のタグで検索します。採掘には、収穫できる道具を持ち替え、材料やアクセス可能なチェストから道具を準備します。木材から板材・棒・作業台を作り、作業台を置いてツルハシを作る工程にも対応します。

地下資源では斜め前を階段状に掘り下げます。頭上の空間と足場を確認し、現在の足元や以前の経路の支えを掘らない候補を使います。着地前の段差移動を失敗扱いにしません。液体・崩落・保護・未ロード領域・ワールド境界等を確認します。

通常の採掘探索はロード済み範囲で、基準地点から水平方向48ブロック以内、ワールド下限の6ブロック上までです。1手順につき最大768回の探索操作・256訪問地点に制限し、残り予算を保存します。資源の近距離検索は各軸半径16ブロック、移動は最大512ブロック先まで128以内の区間予約で進み、各中間点への実到着を確認します。追従とブロック編集を行う作業経路は128以内です。地下からの帰還は歩いた経路を優先します。鉱石の生成位置や障害物によって、探索範囲内に目的の資源がない場合もあります。

歩行経路は8方向A*で広く迂回を調べます。地形の判定と経路をキャッシュし、地形変更時や追従先の移動で再探索します。各NPCは1回512ノード・約0.75ms、サーバー全体は1Tick4096ノード・約2msを目安に中断・継続し、毎回の全探索を避けます。時間は実行環境による目安です。探索1件は65,536ノード、240Tickまで。未ロード境界や上限で歩行経路の有無が確定しない場合は、ブロックを置いて代用せず理由を返します。未ロードのチャンクを検索のために強制ロードしません。

## 障害物・足場・橋

既知の採集対象にそのまま届かない場合、`work_route`は広い歩行迂回を先に探します。歩行で届かないことを確認してから、必要な掘削・設置を含む経路を作ります。葉を手前から除去し、高い木には土・丸石等で階段状の足場を置きます。自分が通った床と頭上の空間を保ち、伐採後の落下物にも接近します。資源の入手は実際にバッグや手へ回収した個数で確認します。明示的な「橋を架ける」は架橋として処理します。

「ブロックを掘ってこっちに来て」「こっちまで橋を架けて」、英語の`Dig through the blocks and come here`／`Build a bridge to me`は、指示理解AIが観察済みの所有者の座標から有限の経路計画へ変換します。対象と終点を指定すると解釈が明確になります。

`work_route`の全引数は`x, y, z, goal, mode, max_blocks`です。goalは`reach`（目的地へ）・`mine`（採掘できる位置へ）・`bridge`（架橋して対岸へ）・`pickup`（落下物の実座標へ）。modeは`dig`・`build`・`both`。buildは持ち込んだ材料のみで設置し、採集のためにも掘りません。bothは不足する土や収穫用の道具を、実際の採集・工作・チェスト等から準備します。橋は同じ高さの対岸に対し、谷底を歩いて代用せず足場を接続します。

経路本体の破壊・設置はmax_blocks=1〜128、編集を伴う探索は各回4096ノード・代替8回、経路の操作は最大512回、全体の待機は10分までです。不足材料を準備するacquireは別の有限処理で、追加の採集を伴います。目的地は開始点から128以内、探索の水平範囲は開始点中心に各軸128まで。編集を伴う上下は開始時より20上・24下までです。未知の巨大建築、液体への直接侵入、破壊不能ブロックやコンテナの破壊は行いません。設置には実在の支持面と実物の材料が必要です。完成した橋や足場はワールドへ残します。

`acquire`は、木材・板材・棒・作業台・ツルハシの段階更新・かまど・原鉄・燃料・鉄インゴット等の依存関係を再帰的に解決します。通常かまどへ実物を投入し、バニラの精錬時間を待って出力を回収します。同時使用を避ける担当情報も保存します。再帰深度・操作数・時間の上限があり、危険・経路・権限・材料の問題は理由を返します。任意の大規模建築やあらゆる加工設備を網羅する機能ではありません。

## 協同作業・常時読み込み・上位計画

近くの同じ所有者のNPCへ、リーダーが`delegate`で資源の準備と実際の受け渡しを割り当てます。一般の担当には`delegate_task`で有限の計画を渡します。割当時は48ブロック以内の利用可能な仲間だけを選び、他人のNPCや既に別の担当中のNPCへ強制しません。担当のUUID・依頼・残数・実完了／保留／取り消しをワールドへ保存し、リーダーの停止・新規指示で子の担当も止めます。委任先からの再委任は禁止です。

同じ協力依頼を受けたNPCはリーダーを一体に決め、要求された最終数量を人数分重複して採掘しません。資源や道具は実際に運んで渡し、リーダーが最終目標の採掘・収納を行います。個別に異なる依頼を出した場合は別の作業として扱います。

NPCがいるチャンクと隣接8チャンクを、NPCのUUID別の永続チケットで常時Tick読み込みします。移動・次元移動時に範囲を更新し、重複するNPC同士のチケットを壊さず、削除時に解除します。所有者が切断中は指示の実行を止めますが、読み込まれた範囲のゲーム時間やかまどの処理は進みます。NPCの人数に応じてサーバーの負荷が増えます。

協力、ネザー、要塞、エンド、ドラゴン等の複雑な依頼は上位計画へ送ります。MOD設定またはホスト側の`config/avatarcraftnpc-ai.toml`の`[ai] complexModel`へ、同じ接続先で利用可能な高性能モデルIDを指定してください。空文字なら通常の`model`（それも空なら接続先の既定モデル）を使用します。Codex方式の上位計画はreasoning effortをhighにします。HTTP互換方式は指定モデルを使用し、互換性のない独自のreasoning引数は追加しません。発言のモデルは通常設定のままです。

長い依頼は最大24手順の段階へ分け、末尾の`plan_next`から検証済みの結果を使って次段階を計画します。最大64段階で止めます。実ポータルの通過、ロード済み構造物参照の観察、実移動による探索、エンダーアイの実軌道の観察、攻撃・照準・弓・アイテム使用等を組み合わせられます。全ツールの引数と実行条件は [ツール一覧](NPC_Tools_ja.md) を参照してください。

新規ワールドからエンダードラゴン討伐までの完全自律完走は未検証です。取引・エンチャント・金床GUI、すべての乗物やプレイヤー専用アイテムの挙動は網羅していません。構造物参照の発見だけで内部踏破や戦闘勝利を達成扱いにしません。

## 最大8か所のロケーション記憶

各NPCは、名前・次元・座標・種類を最大8件保持し、ワールドのNPCデータとともに保存します。近くで確認したアクセス可能なチェストは `chest_1` 等の名前で記憶します。満杯の場合は他の記憶を勝手に消しません。同名の記憶は更新でき、不要な名前を忘れることで枠を空けられます。

近くの所有者のチャット、またはGUIの指示から、例えば次のように依頼できます。

- 「このチェストを『拠点』として覚えて」
- 「覚えている場所を教えて」
- 「回収地点のダイヤモンドを拾って、拠点のチェストへ戻して」
- 「『回収地点』を忘れて」

自然文の解釈は現在のAIに依存します。最初に目的地の場所を確認・記憶させてください。記憶した場所を使う計画では、出発時に収納先を固定し、回収先の別チェストへ目的地を変更しません。別次元へテレポートすることはありません。チェストの撤去・施錠・保護・経路の変化は現地で再検証します。

内部の計画には `location` を指定できます。`pickup` は地面のアイテムを回収し、`collect` は採掘・回収します。どちらも実際の所持数で判定します。`deposit`・`withdraw`・`give_item` は実際の移動個数を記録します。`remember_location`・`forget_location` は `observe` の権限でも利用できます。指示理解・発言のセッションに直接の行動権限はありません。

## モデルと評価

モデル形式はversion 4。48特徴量→1000→1000→1のReLU MLPを5専門家として持ち、汎用・農業・収納、工作・精錬、戦闘、次元移動・探索、地下資源の状況で振り分けます。**5,255,005パラメータ、21,020,020 bytes（約20.05MiB）** のFP32重みを実学習して保存します。パディングは含みません。各候補は1専門家だけで評価するため、1判断で全5専門家を計算しません。重みはサーバー内で共有します。

日英の命令と構造化した状況・行動候補を192,000組で40epoch学習し、別テンプレート／乱数の12,000組で検証、さらに12,000組で独立評価します。命令は合計432,000文、元のシナリオは138種類です。同じ指示でも状況を変えた例を含むため、文面のユニーク数とは異なります。実際の件数・ハッシュは生成先のmanifest.json、学習条件・評価はaction-policy.jsonに記録します。

学習するのは候補の順位であり、生の日本語・英語をローカルモデルだけで理解する方式ではありません。指示理解AIには関連する日英の参考例を最大3件提示します。「少し」「いつもの場所」「さっきの続き」「不足分」「特定の樹種以外」などを、実際の持ち物・場所記憶・検証済み進捗と組み合わせます。補えない参照は確認が必要な理由を返します。数量を省略した資源は原則8個、「少し」は4個、道具は1個を上限のある初期計画の目安とし、解釈は計画の要約へ記載させます。

採用条件は最適候補選択98%以上、合法な緊急候補の優先99.9%以上、実行不能候補の誤選択0件です。同じ効用の候補は複数正解として扱います。これは合成候補評価であり、自然文の解釈率・実ワールドでの任意の作業の成功率ではありません。Javaの推論時間はtools/NpcPolicyBenchmark.javaで測定できます。ワールド探索・経路探索・API遅延は別途必要で、多数NPCでの実負荷も確認してください。

同梱重みの検証最適選択率は99.075%、独立評価は99.15%。両方で合法な緊急候補の優先は100%、実行不能候補の誤選択は0件でした。初期重みを保持した再実行で重みのSHA-256一致を確認しています。開発PCのJava 25では24候補を1,000回ウォームアップ後に1,000回測定し、p50約8.43ms、p95約9.06msでした。これは推論だけの値です。

原木・板材の総称は`#minecraft:logs`／`#minecraft:planks`として実際のレジストリタグに一致させます。オークだけに固定せず、混在した樹種の所持数・収納数を合算します。トウヒなどを指定した場合は樹種を維持します。木製ドアは経路探索で通行対象となり、権限のある所有者のNPCが開閉します。鉄のドアを素手で開けることはありません。作物の自動収穫では未成熟の作物やサトウキビ等の根元を対象から除き、種の植え付けには実際に所持している種と通常の`use_on_block`が必要です。農地の新設から全品種の栽培までを自動化した完走試験ではありません。

専用サーバーでは、材料からの道具準備、地上からの掘り下げと深層鉱石の採掘・帰還、離れたアイテムの回収と元のチェストへの収納、8件の記憶のNBT保存・復元、液体と破壊不能ブロックの回避を検証しています。実AIの日英解釈の品質や、あらゆる地形での安全を保証する評価ではありません。

専用サーバー試験には、空手の2体での道具準備・配送からダイヤ1個の採掘と収納、実かまどの中断・再開、新設チェストへの収納、3×3チケット、実ポータル、弓・エンドフレーム・ドラゴンへのダメージ、死亡と呼び戻し、コンテナとドアの開閉、樹種をまたぐ原木の採集・収納、成熟作物の収穫と実際の種による植え付けを含みます。完全な長期遠征の完走率を測った試験ではありません。

## 学習手順（開発者向け）

学習時だけPython・NumPy・PyTorchを使用します。検証環境はPyTorch 2.12.0、NumPy 2.2.6です。GPUは任意で、CPUを使う場合は `--device cpu` を指定します。配布するJARにはPython・PyTorchを含めません。

```powershell
python tools/generate_npc_curriculum.py
python tools/train_npc_policy.py
.\tools\dev.ps1 -Task test
.\tools\dev.ps1 -Task runNpcGameTest
.\tools\dev.ps1 -Task build
```

`train_npc_policy.py` はversion 4のトレーナーを呼び、ネットワーク接続なしで学習します。既定はseed=61279、40epoch、AdamW、2048件バッチ、学習率0.0001を12epochごとに半減します。教師効用のMSEと同等の最適候補への分類損失を併用します。再学習前の重みを生成先のinitial-policy.binへ保存し、初期重みのハッシュも記録します。このファイルを保持すると同じ初期状態から再学習できます。

`TrainingData/npc-v4/`に圧縮JSONLとmanifest.jsonを保存します。各行は日英の指示、観察条件、想定計画、48特徴量×6候補、chosenを持ちます。学習と検証・独立評価で同じ候補配列が混入していないことを検査します。命令・観察・計画は参考例とデータ監査用、学習入力は構造化した候補です。未成熟や所持不足などは実行系でも再検証します。

`action-policy.json` に構造・初期状態・学習条件・評価・SHA-256・専門家ごとの照合用出力、`action-policy.bin` に重みを保存します。Javaは容量・ハッシュ・構造・有限値・推論照合値を確認します。GPUやライブラリを変更した場合は再現性とJavaの出力を再確認してください。

実行例はローカルで抽出し、人が正解を確認して追加できます。

```powershell
python tools/export_npc_policy_examples.py "run/saves/対象ワールド/avatarcraftnpc/journal" build/policy-review.jsonl
```

抽出用JSONLは `modelVersion: 4`、48特徴量の `candidates`、選択された `chosen`、`reviewed: false` を持ちます。自動選択は正解ではないため、人のレビューなしに学習へ追加しません。現行トレーナーの既定入力は生成済みカリキュラムで、抽出ログを自動取り込みする機能はありません。学習・検証は別ワールドや別課題で分けてください。名前・会話・所有者UUID・ロケーション名・委任計画本文は抽出しませんが、操作の座標等は含むため共有時は内容を確認してください。

候補の精度だけでなく、道具不足・危険・経路なし・記憶したチェストの撤去・満杯・切断・途中再開・複数NPCで、完了率・誤完了・回復・遅延を確認してください。採用する際はJSONとBINを対で `src/npc/resources/data/avatarcraftnpc/ai/` に配置します。ゲーム中の自動学習やログの外部送信は行いません。
